## 四、大体积 PDF 的判断与方案（用户问「保留 PDF 备份＋单独做 PNG 图片版，还是你有更好的办法？」）

### 判断：**主交付不再依赖 PDF；PDF 只留作印刷／归档备份。**

理由：GitHub 对仓库内单个大 PDF 的在线渲染有限制，29.9MB 已实测报
`Unable to render code block`；这不是文件损坏，也不是沙箱内存溢出，而是**单文件预览上限＋
浏览器渲染链路**问题（GitHub 社区讨论里大 PDF 报同一错误，也有人由浏览器扩展／网络触发）。
只做「一份 PNG 图片版」仍然要用户逐张在 GitHub 上点开或自己从 PDF 转图，
没解决「网页直接看」和「一次拿全」两件事。

因此提供三件套，互不替代：

1. **`deliverables/第三话_逐页看图.md`** — 12 张 PNG 以相对路径内嵌，
   GitHub 网页直接逐页显示，不下载、不转图，右键可单张另存。这是最常用的入口。
2. **`deliverables/第三话_12页PNG图片版.zip`** — 12 张 1440×1920 PNG 原样打包
   （`ZIP_STORED`，PNG 已压缩不二次编码），一次下载解压即得全部页图；
   逐张字节等同正式 PNG 母版。
3. **`deliverables/第三话_轻量在线预览.pdf`** — 12 页、720×960、
   JPEG q=88（4:4:4、从原 PNG 一次编码、不重复转存）、**2.15MB**，
   页面物理尺寸仍为 691.2×921.6pt，供连续翻页／打印草稿。
   按长期记录第十二节要求，使用 JPEG 已记录质量参数，并渲染回读放大目检：
   台词、页码、线条均清晰可读，12 页顺序无缺页。**明确标注为非定稿预览**。

**保留不动**：`第三话_妹妹的休息日.pdf`、`第三话_竖屏全页漫画.pdf`
（各约 37MB、12 页、PNG/Flate 无损、逐页 150dpi 对 PNG `max_pixel_diff=0`），
作为定稿画质与印刷／归档备份。定稿画质不以轻量版为准。

生成脚本 `scripts/export_lightweight_preview.py`；
校验脚本 `scripts/verify_chapter03_pdf.py`（同时校验两份无损 PDF、轻量 PDF、ZIP、看图页链接）。

## 六、沙箱资源检查（用户要求「检查内存是不是溢出了」）

实测无溢出，也没有 OOM 迹象：

- 磁盘：`/dev/root` 21G，已用 3.7G，可用 **17G**（19%）。

  不是本轮内存异常。
- 两份 37MB PDF 用 `pdf_export.py` 直接嵌入 PNG IDAT 流，生成过程不解码全页位图；
  构建实测 2m32s，期间内存稳定。

  已用轻量 PDF＋逐页 PNG 看图页绕开。
