## 三、耗时实测与增量优化（用户问「为什么每次这么久、是不是做了多余工作」）

**结论：长耗时不是必须的，主要来自三处多余工作。**

| 实测项 | 数字 |
|---|---|
| 单页 1440×1920 `im.save(optimize=True, compress_level=9)` | **6.70 s/页** |
| 24 页（12 阅读＋12 竖屏）全量重编码 | ≈ **161 s**，与旧 build 实测 **2m32s** 吻合 |
| `ImageChops.difference` 像素比对 | **0.104 s/页**，24 页 ≈ 2.5 s |
| 旧流程改 3 张源图 | 仍全量重编码 24 页、重写两份 37MB PDF、重建 ZIP／轻量 PDF |
| **增量后**改 3 张源图 | **39.98 s**（只重编码 6 页，跳过 18 页）＋导出 1.93 s |
| **增量后**无任何改动重跑 | **0.156 s + 0.201 s**（哈希短路，连绘制都不做） |

多余工作清单：①未变化页反复做 level-9 PNG 编码；②每次重写两份 37MB 无损 PDF 与
36MB ZIP／轻量 PDF；③每次全量重跑本可增量复用的审计；④把同一段结论复制进 8～10 份文档，
导致一处判断错了要逐份回改；⑤对同一张失败图连续局部重绘 4 次，最后仍整张弃用——这是
最昂贵也最没价值的一段工作。

已落实（`scripts/build_chapter03_v4.py`、`scripts/export_lightweight_preview.py`）：
- 源图＋构建脚本哈希短路：全无变化时直接退出。
- `save_png` 先做像素比对，内容未变跳过昂贵编码；按变化页决定是否重写派生 PDF。
- 轻量三件套按 12 张母版字节哈希短路。
- 缓存文件 `.build-cache.json` / `.lightweight-cache.json` 已加入 `.gitignore`，不入库。

**仍必须保留的耗时**：实际生图、逐页人眼目检、交付前一次全量几何／画布／PDF 校验。
这些是验收，不是多余工作。

## 四、新增铁律（已同步 `AGENTS.md`、`PROJECT_MEMORY.md`、长期记录第十七节）

1. **先数袖管／手臂，再数手指。** 逐角色从肩线往下追每条袖管，每条必须连到一只手；
   袖管总数＝手臂总数。有空袖口、悬空前臂、桌下多出的袖管，一律判多余肢体，
   不允许靠放大手指局部来「确认没问题」。
2. **异常轮廓不得自辩。** 出现叠掌、第二排指节、横压手背的手指、游离小拱形／指尖、
   空袖口，直接判失败。禁止用「拇指绕柄」「衣褶」「反射」「透视」解释成合理解剖；
   除非能与已验收的同款画法并排证明，且用户视角看不出异常。
3. **用户截图是验收基准。** 返修后必须按用户同一视角、同一区域裁切，与用户截图并排复看；
   用户说「还是」「又」时，上一轮验收结论自动作废，不得复用上一轮的话术和解释。
4. **生成成功 ≠ 修复；脚本 PASS ≠ 修复；文档写「已修」≠ 修复。** 只有 `read_file` 打开的
   实图、按用户视角清点通过，才允许写「已修」。文档里任何「已修／正常／确认」类断言，
   提交前必须逐条对本轮实图 grep 复核，无实图支撑的一律删除或降级为「待复核」。
5. **同一处局部重绘最多两次。** 连续两次仍不通过，必须整张弃用、换成更简单的构图
   重新生成（减少需要同时画对的肢体与道具），不得继续打补丁。宁可改构图，不要改解释。
6. **道具状态机前置。** 任何跨页道具在生图前先写逐页状态表（手持／落地／画外、
   谁、哪只手、理由）；状态变更必须实际生图，禁止排版合成或只改文档。
7. **效率铁律。** 源哈希＋像素比对增量构建，只重建变化页与派生交付；禁止无解释的
   全量重建、全量重复审计、全量文档重写；单一事实源＋指针，不把同一结论复制进多份文档。
8. **交付前用「用户会看哪里」反向清单**，而不是只跑自己写的脚本；并保留用户截图反例库、
   同错指纹清单（横压手指／第二排指节／游离小拱形／空袖口／桌下多出的手／叠掌握勺）。

  正确动作是数袖管，不是继续放大手指。这是本次最核心的能力缺口。
- **需要学会在第二次失败时换方法，而不是加 prompt 约束词**：4 次局部重绘的失败
  说明生成模型在该构图下无法收敛，应该第 2 次就整张换构图。
- **还需要**：①用户截图反例库（把 `image-14/15.png` 这类截图的裁切与判定存进

  生图输入与交付验收表；③同错指纹清单；④增量构建缓存（已做）；
